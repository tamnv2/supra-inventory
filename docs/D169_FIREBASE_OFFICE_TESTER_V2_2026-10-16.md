# D169 Firebase / Google Office connectivity test v2 — evidence-only

**Date:** 2026-10-16 (Vietnam). **Purpose:** Owner-requested standalone Windows x64 read-only network diagnostic for Firebase/Google provider alternatives. This is not a new Agent production EXE release, not an APK update, not new Firebase Rules, not a Beta/Stable deploy and not permission to activate paid services.

## Source-backed prioritization

Current code: `relay-agent/RtdbHaLiveness.cs` uses RTDB only for ephemeral HA liveness, while `FirestoreAgentLeaderCoordinator.cs` preserves authoritative Firestore generation/roles/lease; `FirestoreConfirmationTransport.cs` + Android `RelayPocClient.kt` still use Firestore durable job plus terminal ACK. `FirestoreHttpTransport.cs` uses Windows `WebRequest.DefaultWebProxy` then `WebRequest.GetSystemWebProxy` in bounded failover. v1 direct TCP failures on corporate network must therefore not be interpreted as provider-wide blocks.

| Existing/potential provider | Why check Office route | What v2 proves / doesn't prove |
| --- | --- | --- |
| Existing registered Beta RTDB endpoint, REST and SSE Accept | Small heartbeat/liveness channel without document read/write billing | HTTP access/proxy reachability, not auth, SSE events, permissions or actual request/ACK delivery |
| Cloud Firestore REST/gRPC front door | Current job/ACK/lease/identity coordination | Direct TLS/ALPN and HTTP route; not authenticated gRPC Listen or billed document reads |
| Identity Toolkit, Secure Token, OAuth, Firebase Installations | Login, token refresh and FCM client support | Transport only; no tokens, accounts or authenticating API calls |
| FCM HTTP v1 + Android FCM TCP 5228–5230 | Notifications, call/chat wake | Publishing host / Office Windows TCP only, NOT a real PDA background notification receipt |
| Existing Gen2 Functions platform, Cloud Run control plane | Existing server-side alert work, event routing | Only generic platform API reachability, not actual deployed runtime |
| Firebase Remote Config, App Check | Configuration and security; NOT realtime data replacement | Generic endpoint reachability, not config fetch or App Check proof |
| Storage, Hosting, Crashlytics, Data Connect | Ancillary storage/telemetry and research; not first-choice messaging | Host reachability; no instance deployment or data mutation |

| Existing Apps Script / Drive / Sheets | Office-accessible current supporting paths | Generic service hosts only; no Apps Script script calls or UrlFetch quota use |
| Existing scoped Beta Worker `/health` | Existing business authority accessibility baseline | GET health only, no authorized server request |

28 targets × 2 rounds = **56 target-rounds**. Of these, 25 HTTPS targets attempt 3 routes each (DIRECT plus two Windows-native .NET proxy selection methods), 3 FCM Android TCP targets attempt direct only: **156 route probes**. External public host tests do not register those services as project resources or allow provisioning. Only the existing in-scope Beta RTDB host and Beta Worker health are project-specific probes; Stable remains excluded.

**Caveats:** HTTP 401/403/404 may be generated by Firebase *or* the authorized corporate proxy; HTTP 407 is a proxy-auth challenge and NOT proof the provider was reached. PowerShell/.NET matches the Agent's Windows proxy API family, but this remains a GET reachability test, not an authenticated Listen, FCM or PickList test. The RTDB probe reads a never-used path without creating/changing any data and asks for SSE content type on an unauthenticated separate probe; request overhead may count towards Firebase bandwidth usage. Generic Cloud Functions/Run/PubSub/etc endpoints do not prove a specific private instance works.
