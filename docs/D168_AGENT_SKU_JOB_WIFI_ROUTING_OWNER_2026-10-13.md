## Owner-fixed behavior (new instructions)
1. Auto SKU is **PRIMARY-preferred at admission**, but any Agent that validly *began* SKU work retains a separate job right through DONE or terminal failure **even if another Agent becomes PRIMARY**. Once one Agent successfully DONE, all Agents must learn status and must not redo the same due slot. The new PRIMARY retries only after the old job is definitely failed, expired/abandoned through bounded safe takeover, or not DONE.
2. **Export before switching network:** when due, use current WMS-capable network to open the existing same-profile isolated WMS export tab, download SKU Excel read-only and parse/validate locally. If direct Cloudflare service probe is successful, upload directly. If unavailable and on approved Office network, prefer approved saved PDA Wi-Fi profile, then other approved saved Internet profiles; on other networks try approved available alternatives. On acknowledged direct Worker DONE, restore the original interface/profile and verify business transport readiness. No unknown or unregistered networks, no network credential extraction, no corporate bypass/bridging.
3. Modeless foreground notification offers **Bỏ qua** (defer 15 min; then ask again) or **Đồng ý đổi mạng**. No interaction for **60 seconds** means consent to attempt the safe transition once all operational guards pass; 60 seconds is *not* permission to interrupt active work or disregard corporate WLAN restrictions. The prompt must never block WMS confirmation or the UI thread.
4. Allow network switch only when **no WMS confirmation, Picker request ACK, pending confirmation wave, HA handoff/failover, privileged operation, active log upload, other network switch, or other conflicting business operation** is underway. Re-check immediately before disconnect, and avoid a new operation admitted between check and switch. Prefer handoff to healthy standby before PRIMARY's Wi-Fi switch. If no standby and a new picklist can arrive, uninterrupted service is not guaranteed; leave job waiting rather than blindly disconnecting the only PRIMARY.
5. Retire Agent's Firebase/Firestore **Usage UI**, auto /15-minute monitoring refresh and D166 Usage ZIP export; Owner will supply screenshots of provider dashboards when needed. Retain Agent operational logs, Drive archive, error/crash uploads, local debug audit and business history. Avoid changing deployed public Gateway endpoints immediately, because older Agents may still call them.

## Essential constraint: pre-export job intent without Cloudflare
The User requirement "once auto SKU begins it can finish after HA loss" requires a durable start/ownership **before disconnect or HA change**. Today `relay-agent/D167SkuCoordinator.cs` exports WMS before Worker `claim`, and current Worker requires current PRIMARY for EVERY `claim/stage/preview/publish`. Because Office-only **cannot directly reach Cloudflare**, Worker cannot issue the new job lease during an Office-only pre-export step without an allowed intermediary. Acceptable *candidates* (not validated releases):
- **Preferred minimal Gateway footprint**: one authenticated Google Gateway pre-admission call while on Office to Worker, creating an immutable, expiring SKU `job_id` lease; export under that reservation, then switch to PDA and continue DIRECT Worker with bounded lease renewals. Exception: if gateway quota exhausted, this admission cannot happen; classify as deferred, not begun.
- **Alternative without Google Gateway**: commit a small, authenticated, CAS/fenced *start-intent* into **an already registered/scoped Firestore coordination resource** while the Agent holds PRIMARY, then have the Worker verify that immutable record and admit the job once direct Internet is available. This requires permission rules, race review, Worker-to-Firestore validation, strict TTL/replay protection and possibly a registered resource change. No new collection can be silently assumed authorized. Absence of such verified trust path means HA-independent continuation cannot be safely guaranteed for Office-only starts.
- **Fallback**: if only the current Worker `claim` after Wi-Fi switch is feasible, call it "candidate local export", NOT an authorized fleet job, and revalidate PRIMARY at claim. That falls short of Owner requirement and must be reported as such.

**Security invariants:** separate `sku_job_owner/job_id/job_epoch` from `firestore_primary_generation`; authorize start only for authenticated role/current HA primary, then allow only holder of a cryptographically unforgeable, short-lived, server-issued scoped job grant (or server-validated immutable start-intent), not any Agent preserving an old generation. All mutations are matched to day+slot+owner+fingerprint+job_epoch and atomic Worker/InventoryCore state; generation loss alone does not invalidate active job grant. Reclaim only once lease truly expires or terminal fail is committed; an old Agent reappearing after takeover is fenced. The existing 15-minute lease was designed for the old model and needs measured TTL/heartbeat policy; do not assume an indefinite non-expiring grant. Manual per-day priorities and 03:00 VN date-boundary/slot coalescing stay authoritative on Worker.

### Durable job state/transport
`SCHEDULED -> RESERVED_PRE_EXPORT -> EXPORTING -> READY_FOR_NETWORK -> WAIT_CONSENT (60s) -> WAIT_SAFE_IDLE -> SWITCHING -> CLOUD_READY -> CLAIMED/STAGING -> VERIFYING -> DONE -> RETURNING_TO_ORIGINAL_WIFI -> RESTORED`. Separate exits: `DEFERRED_15M`, `FAILED_RETRYABLE`, `FAILED_FINAL`, `LEASE_EXPIRED`, `FENCED`, `RESTORE_FAILED`. UI must show **SKU DONE** only when Worker durable receipt/fingerprint verified; **NETWORK RESTORED** is a separate fact. On post-publish timeout, query same `job_id` for DONE before any retry; never republish blindly.

Worker is business authority: exactly one active SKU job per day/slot; `DONE` receipt is immutable/idempotent; historical SKU remains for previous-day reporting. New PRIMARY sees `RUNNING` and waits without re-exporting; once DONE, no new job. For no-network during pending operation, use a bounded lease and a single safe takeover if the owner disappears; no infinite blocking. Prefer event/piggyback on existing Agent sync to disseminate `job_id/slot/state/revision` compactly, **not one Firestore write per stage or per second**. Workers secure CAS always wins over stale UI and stale Firestore projection. If Office Agents cannot reach Cloudflare, a once-per-status transition Firestore projection may be required; measure reads/writes and validate existing scope/permissions. Preserve FCM/Firestore for live PDA confirmation and notification as needed.

### Exact network switching
A capability probe to the registered Beta Cloudflare health/status endpoint must validate HTTPS with correct TLS/expected host (not generic 'Internet available' or ping); the business `DONE` write confirms actual usability. Capture WLAN **profile name vs SSID**, interface GUID, effective route/proxy, original profile and connectivity state; do not infer a saved profile from visible SSID. Windows `WlanConnect`/preconfigured `netsh wlan connect` typically works for a standard account with execution rights on that saved profile; domain policy/EAP might deny. Microsoft docs: https://learn.microsoft.com/en-us/windows/win32/api/wlanapi/nf-wlanapi-wlanconnect and https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/netsh-wlan .
- Whitelist network profiles approved for this scope, retry Office->approved PDA first, then alternative approved Internet profile. Never capture or log passwords/profile XML/private SSIDs to public GitHub. No Wi-Fi scanning/connect to unknown networks or IT network-filter bypass.
- Do not start an expensive WMS export if an earlier valid `DONE` receipt exists. Export only from an already authenticated authorized WMS browser, before Windows Wi-Fi disconnect; WMS session/browser stays in memory and is revalidated after restoring Office, not falsely marked READY during switch.
- During 60s toast the user can skip (15-min alarm). If user ignores, **eligible** when UI idle safety gates hold; if unsafe, show "Chờ thao tác đang chạy" and reevaluate through existing local events, never forcibly interrupt. After retry deadline a stale export must be revalidated or discarded, not published under expired job permission.
- While switching, protect incoming business confirmations by prior explicit HA handoff and generation fencing, or cancel/postpone and restore original network immediately. A momentary break of the only PRIMARY's Wi-Fi is an availability impact even if no confirm was active *at a particular instant*.
- Keep local sanitized snapshots/log journal `intent/owner/slot/SSID category/probe decision/upload phases/DONE receipt/restore`, but do not store raw WMS XLSX long-term or secrets. Show actual operator on manual action.
- Force rollback to original network after error too, including early 401/403, DNS fail, captive portal or timeout. If original Wi-Fi unavailable, alert persistent unrecovered state and do not report original network restored.
