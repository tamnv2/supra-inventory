It already has privileged-Auth fallback and request_support_logs. Avoid adding a new project/function until its realistic traffic/reliability/UrlFetch quota are measured. For Kick preview/revoke, consider narrowly expanding this registered Gateway with fixed allowlisted actions and Worker authoritative bearer verification, nonce, request_id idempotency and terminal 401/403. Do not accept `200 Gateway` without verified Worker commit/result or let Office clients write Worker business tables through Firestore without server validation. This option still uses UrlFetch quota shared with existing scripts, so it is a SHORT-TERM alternative only if proven stable/cost-effective.

**Phase B (only if A inadequate and approved as a new scoped resource):** one tiny HTTPS Cloud Run function in existing registered `gcp-beta` project (`asia-southeast1` candidate; actual region after provider/Office preflight). No general purpose pass-through, no arbitrary URL, no service token in WinForms, no impersonated admin. Local Office test URL must verify function HTTPS through real corporate proxy before paying/deploying. If Cloud Run IAM invoker requires a service account, do NOT embed service-account key in Agent; use properly authorized backend-to-backend identities. ## Global log rollout hazards and cost model

- A 13:15/21:15 slot is a logical dispatch boundary, not a guarantee exactly at that minute from devices asleep/offline. Android WorkManager can run later; Agent must be running; Web server logs run with no visitors, Web client journal only after next live tab.
- Approximate upper planning case: 500 active Android × 2 daily slots = 1,000 upload attempts/day **before** retries/logout/manual and any multipart chunks, 30,000 monthly. 0–15-minute per-device stagger gives approx 1.1 attempted uploads/second if 1,000 uniformly spread; this is NOT a measured provider bill or a guarantee that all 500 devices are online. At 16KiB per bundle this is 16MiB/day (~480MiB/30-day month) before multipart metadata and other clients; larger Agent bundles/retention can dominate Drive/storage. Pay attention to Drive daily upload API quotas and Worker invocations. Avoid duplicate READ/WRITE per retry by stable archive ID and source cutoff.
- Retention 45–60 days MUST be scoped to already registered Drive/Worker policy. Pending local queue cannot be deleted until Drive archive receipt. Bound number/bytes and expose overflow without silently dropping unarchived evidence.
- 21:30 screenshot is only 15 minutes after 21:15 dispatch. With jitter, retries, server buffering and cloud ingestion some logs are still pending. Publish a PROVISIONAL daily report at 21:30 and update after next-day sync with explicit revision and coverage.
- Daily screenshots are official dashboard *estimates* of Firestore usage, not necessarily exact billed records; Google Cloud Billing and Cloudflare invoiced items are separate source of truth. Firestore quota resets at Pacific midnight, separate from VN workday.
- Logged-in global support command sent by Agent cannot compel browser that is closed to upload its RAM journal, or a power-off/disconnected Android/Agent to wake. System-wide request returns coverage summary: RECEIVED / ARCHIVED / RETRY_WAIT / NOT_REACHABLE / NO_SESSION, with trace request id; no fake 100% receipt.
