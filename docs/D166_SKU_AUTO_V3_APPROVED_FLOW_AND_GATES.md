## Owner's required end-to-end flow

1. Starting **05:00 Asia/Ho_Chi_Minh** each calendar day, when an authenticated Agent becomes PRIMARY and Web Confirm + Supra login are stable, it may attempt SKU synchronization. A standby cannot start the automatic job.
2. The Agent invokes a **separate low-impact WebView2 browser view** sharing the current Agent-owned browser environment/session state through supported WebView2 behavior. It navigates the exact approved WMS UI route **`https://wms-supra.winmart.vn/sft3/app/report/bin-inventory`**, interacts with the *documented, uniquely identified* sync/export controls by UI events and downloads an Excel file. No programmatic WMS API, cookie scraping, token/profile copying, DOM injection into Confirm target or authorization bypass.
3. The same Agent's **authenticated Firebase Agent identity** is used as a distinct Agent API authority for a narrowly scoped upload/import operation in existing **Beta Worker/InventoryCore**. **Do not impersonate a WEB session** or pass Agent tokens into the companion browser. The Agent process must retain the credential and make the service requests itself; the companion only produces an inert locally validated file/evidence.
4. Parse source Excel with parity to the existing Web `parseSkuExcel` contract (true `.xlsx`, <=50 MB, <=50k rows, header within first 20 rows, SKU text precision checks, duplicate+conflicting name discrimination). Import only `SKU` and `product_name`; never persist bin, location, quantity, personal data, or unrelated WMS fields. Validate filename extension **and actual OOXML structure**, size, freshness, full download completion, and SHA-256; reject partial/old/ambiguous files.
5. Use existing authoritative Service `/business/skus/import-v2` semantics for **preview** (dry run), conflict resolution, chunks (<=2000) and idempotency. Agent UI displays the exact preview counts and requires direct Agent confirmation for conflicting name updates; do not silently overwrite names. Missing SKUs in source are never deleted. Existing PUSH `sku_catalog_updated` and silent FCM invalidation to online PDAs must remain intact. Only server-verified aggregate import success + catalog checkpoint mark **DONE**.
6. Automatic mode: exactly **one winning Agent per Vietnam calendar day**, keyed by a **Service-authoritative atomic daily lease/checkpoint**, not only a local flag or Firestore client presence. Lease has bounded expiry with explicit `claimed/preparing/preview/committing/done/failed/needs_user_confirmation` states. No second import while any first job is pending or in uncertain commit; restart/retry uses stable idempotency identities. On multi-Agent failover, re-check primary generation and server lease before service mutation. All other Agents observe `DONE` and skip until the next day after 05:00.
7. Manual **`Cập nhật SKU`** button on Agent: require `VerifyCurrentAgentPasswordForAction` with current OTP/emergency proof for privileged accounts and established local verifier for ordinary allowed Agent accounts. A verified manual invocation may request an authorized **new run** even after that day's auto DONE, with separate audit and no duplicate in-progress mutation. Never store/transmit the raw proof in local logs or companion child command-line.
8. Isolate WebView2 URL/session/events, downloader, Excel parsing and Service upload from Confirm Picklist WebView, leader election, scheduled reload and ACK latency. No new Firestore/RTDB listeners or cron/read loops. Trigger after existing Agent readiness/role transitions and when waking after 05:00; do not add short-interval polling. A PRIMARY under active job load must defer potentially heavy UI/download/parse work until Confirm is idle; do not independently refresh/kill its browser.
9. Manual errors prompt with actual status on **Agent**, not Inventory Web. Download/source parse/auth/quota/409 name conflict/network/timeouts/role loss/partial import all fail closed with replay-safe progress. The operator can retry only under explicit safe state, and a second automatic Agent cannot falsely mark DONE.
10. Logs use bounded redacted event stage, timing, file digest (only for local matching; prefer truncated/hash), rows/conflict counts, HTTP status class, Service authoritative checkpoint, leader epoch alias and IDempotent replay category. No credential, raw SKU, PL, WMS request/response payload, typed input, token, cookie or raw file path. Keep the D166 usage comparison baseline; no provider-write per local event.

- `relay-agent/Program.cs` stores an authenticated `AgentSession` with `IdToken`/`RefreshToken` and role; `FirestoreAgentLeaderCoordinator` provides PRIMARY role+generation and protected verification before WMS mutation. Existing `VerifyCurrentAgentPasswordForAction` supports privileged remote reauthentication versus local verifier.
- `service/src/index.ts#requireAgentUser` accepts valid AGENT/channel-less ID token only for ready ACTIVE ADMIN or PICKPACK_ADMIN with base_role equal role, unlike Web `requireUser` which requires WEB/ANDROID interactive generation.
- `service/src/business-api.ts` import route requires authenticated WEB and `service/src/sku-import-core.ts` exposes bounded chunk dry-run/409/conflict and idempotency. A **new Agent-specific endpoint** or authorization adapter must be added; copying an Agent token into the Web route is not safe or functional.
- Owner-provided v1.1 Recorder JSONL is **13 events**, local `.xlsx` download+file selection evidence; **zero `UI_ACTION` records**, and no imported-file bytes, page DOM, selector fingerprint or service-result evidence. It cannot establish the actual Bin Inventory sync/export button selectors, report response validity or actual workbook column mapping. **Do not invent an auto-click sequence** or claim that source data can already be parsed/imported.
- Existing Agent browser `WaitForPageTarget` can attach to the first WMS host; companion tab creation risks selecting the wrong target after Confirm reconnect. Explicit target affinity/isolation regression must PASS before PRIMARY activation.

## Safety gate and missing field evidence

**BUILD BLOCKER FOR FUNCTIONAL V3:** exact, trusted Bin Inventory UI controls/actions and an actual authorized SKU export workbook schema are not present in the supplied log. Without both, automatic clicking and full direct import would be guesswork. Implement **fail-closed diagnostic mapping in a test-only standalone build** before enabling any mutating end-to-end job. Gather (a) click-target structural selectors and postclick DOM state without free-form text or credentials, and (b) Owner-provided sanitized sample workbook or on-device validator evidence (column headers/types, row count, duplicates). Only after both are proven should the implementation permit auto click/Service submit.
