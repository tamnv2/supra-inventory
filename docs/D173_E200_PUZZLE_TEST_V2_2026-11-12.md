# D173-E200 — Standalone Puzzle Tester V2: one-click field experiment

Date: 2026-11-12. Scope: independent diagnostic browser code only; no Agent Production, Host, Worker, Web, Android, Firebase, D172, Stable or provider changes.

## Owner authorization
- Owner states the target WMS permits automated interaction with the image-matching puzzle. Record as an **Owner assertion**, not independently verified vendor documentation.
- Owner manually navigates to an already-displayed puzzle. The browser must **not** find or click Login and must not read or retain user/pass/token/cookies/forms/URLs.
- Pressing **Test** may send a **maximum of one drag** after in-memory screenshot geometry analysis. Never retry automatically or submit any credentials. Afterward the Owner explicitly labels **PASS** or **FAIL**.
- A low-confidence or ambiguous visual match must **not drag** and must log a non-attempt reason.
- Logs are generated locally on explicit Save only, and contain only numeric geometry, viewport dimensions, confidence category, attempt flag, and Owner verdict. Do not store screenshots automatically or send logs to any cloud endpoint.

## Implementation and limitations
- Derived from V1 standalone WebView2 browser in Draft PR #930; V2 branch keeps the same InPrivate profile isolation and disabled password/autofill.
- Visual detection starts from the colored drag handle in the **current screenshot**, then looks for two matching jigsaw contours at measured positions. It does not use any fixed drag displacement from past logs. Uses local OpenCvSharp image processing.
- For input the browser only reads `window.innerWidth`/`window.innerHeight` (viewport size) and sends one bounded DevTools pointer drag with a 25-step path. No DOM text, network interception, credential capture, query to WMS APIs, or provider-side mutation outside the user-requested drag.
- Model is **experimental**: 3 V1 geometry-only traces and 6 still images do not prove accuracy. Screenshots are processed in RAM and not retained. Wrong matches are possible; a confidence/ambiguity gate suppresses many, not all, uncertain cases.
- Main risk: rendered layout / DPI / iframe input composition and false-positive image contours. Field tests must record attempted versus not-attempted, Owner PASS/FAIL and exact context-independent numeric geometry. No implied success from source CI.
- The WebView2 InPrivate subprocess may retain temporary OS cache until closed; V1 best-effort cleanup remains, no absolute no-write guarantee.
