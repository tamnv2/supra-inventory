## Ma trận bắt buộc

| Gate | Kỹ thuật kiểm | Quy tắc |
|---|---|---|
| 60 kết nối realtime mô phỏng | Node 22 + 60 WebSocket Upgrade cùng Durable Object local | Phải thành công, ghi latency |
| Burst >=20 lệnh/5 giây | 20 REPORT với 20 SKU giả | <5s trong CI local chỉ là tiền đề, **không đại diện mạng thực** |
| Retry/idempotency | 20 lệnh WS replay HTTP cùng request ID | Không tạo trùng batch/ticket/event |
| Reporter/CAS/ACK | 20 giải quyết, một ACK | Không sai version, đúng recipient |
| Reconnect, event recovery và >201 sự kiện | 15 reconnect, 225 event mới, RECOVER(limit=100) | **Không được đánh dấu covered-through bỏ qua event chưa trả** |
| Bảo mật | Server định danh client | LAB dùng query UID → **FAIL đối với Production auth** |
| Core/clients thật | Chạy cùng code release \`InventoryCore\`, Web, APK, Agent | LAB standalone → **FAIL** |
| D172, WMS/Firestore, HA, FCM, SLA 03:00, SQL error | Full regression shared Worker và field | **FAIL nếu chưa chạy có chứng cứ** |
| Usage thực/chi phí toàn kỳ | Provider read-only Cloudflare/Firebase/GCP và cảnh báo | Không dùng counter LAB để kết luận |
| Owner release gate | Chỉ sau khi đạt tất cả tiêu chí kỹ thuật và được Owner chốt | OWNER-GATED |

**Quyết định mặc định: RELEASE_READINESS_FAIL.** Chỉ chuyển PASS khi tất cả ô có chứng cứ đúng phạm vi, không dùng CI unit green để thay thế test field/chi phí. Trạng thái kỹ thuật local PASS, nếu có, được ghi riêng. Artifact \`release-readiness.json\` và \`release-readiness.md\` gồm lý do chính xác; CI hard gate **đỏ là cố ý** nếu chưa đủ release, không phải sự cố cần xoá gate.

## Ghi chú so sánh

\`read-model-core.ts\`, \`operational-v2-core.ts\`, \`web/src\`, Android chính thức và Agent hiện hành là source authority; \`tools/d173_e110_sandbox\` chỉ mô phỏng khoảng hẹp một số chức năng. Fixture 60 sockets dùng ít user ID, khác 60 PDA có tài khoản, phiên, thiết bị, kết nối không đồng nhất. Các phép tính Cloudflare bills của LAB là mô phỏng, không khẳng định tiết kiệm thực. Kết quả burst local không chứng minh p50/p95/p99 ngoài mạng kho.

## Quy trình tiếp

Nếu RELEASE_READINESS_FAIL: chưa được phát hành; không merge PR804/805/806/E111, không đổi app trong ca. Muốn đạt PASS thực tế phải tích hợp đúng code hiện hành trong runtime riêng, test tương thích hai chiều HTTP/WS dưới phân quyền thật/giả lập bảo mật phù hợp, failover, D172, rồi đo usage/cost provider với quyền Owner và môi trường cách ly.
