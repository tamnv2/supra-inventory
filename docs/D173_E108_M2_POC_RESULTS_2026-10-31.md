## Scope và cách đối chứng

`tools/d173_e108_m2_poc.py` dùng SQLite trong bộ nhớ/file tạm với một hàm `dispatch()` dùng chung cho hai **adapter giả lập** HTTP và WS. Mỗi command tái kiểm tra phiên/role; kết quả và request ID ghi cùng transaction với business state và event audience; CAS/version; correction/withdrawal window; ACK chỉ cho Picker sở hữu ticket. `recover()` trả event đã lọc theo audience và cursor **covered-through**. Giao dịch lỗi rollback, retry cùng request ID nhận cùng kết quả, retry qua fallback HTTP không tạo bản ghi lần hai.

`tools/test_d173_e108_m2_poc.py` kiểm tra idempotency, chuỗi report/group/resolve/correct/withdraw/ACK, phiên hết quyền, hai picker xen kẽ không gây false gap, cursor/retention/epoch, phân trang >200 event, restart SQLite, lost ACK, CAS, burst 20 picker/5s ở cấp chức năng (không bắn traffic thời gian thực). Fixture tự tạo mã giả `p1`, `SKU-A`; không chứa mã nhân sự, dữ liệu người dùng hoặc secret.

Workflow `.github/workflows/d173-e108-m2-poc.yml`: Python 3.12 unittest, regression realtime hiện hữu, secret guard, E107 offline budget selftest; không credential, không gọi Cloudflare/Firebase.
